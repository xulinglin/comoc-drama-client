# 连续性账本与战斗节拍

本文件是连续性和战斗动作的唯一详细规则。`SKILL.md`、分镜规则和质量校验只保留入口，不重复扩写。

## 连续性：事实账本

### 用提示词维持空间连续性

先确定场景地标、固定方向和人物动作轴线，再按连续状态链切分素材。每条素材的提示词都应独立包含以下信息；没有的项目明确写无，不为填字段添加剧情：

1. 场景与开场：场景 ID、固定地标、人物相对地标的位置、相互距离、支撑面和接触关系。
2. 人物状态：姿态、身体朝向、视线、左右手持物、道具朝向、伤势和装备；群体写总人数、可见人数、分组位置与运动方向。
3. 摄影机：位于人物或场景的哪一侧、高度、景别、朝向、画面左右与前后遮挡；画幅继承项目。左右手始终指角色自身左右。
4. 动作过程：从上述状态起手，明确移动路径、接触或交接、对方反应和收势。动作导致的位置、持物与人数变化进入结束账本。
5. 结束画面：明确最终站位、姿态、持物和机位，不用“恢复原位”“保持之前”等外部指代。

`state_in/state_out` 的位置与朝向使用场景固定坐标或地标，例如“门内东侧一米、面向西”。不要用“画面左侧”作为跨镜事实：换机位可以改变画面左右，不代表人物移动。画面坐标、镜头位置及视线投影进入 `spatial_state/end_state`。默认保持动作轴线一侧；确需越轴时用可见运镜或明确建立镜头交代。

例如：“CHAR-001 在门内东侧一米处面向西，右手握 PROP-001，左手空；CHAR-002 在门内西侧一米处面向东，两人相距两米。摄像机在门内南侧、距地1.5米，中全景；CHAR-001 在画面右侧，CHAR-002 在左侧。”下一镜若改为北侧机位，世界状态仍相同，画面左右则重新描述。

自然语言、账本和首幕必须表达相同事实。复制上一条结束账本只能保证数据交接，还要检查动作是否真正导致该结果。未生成视频时不得声称已验证成片连续性。

长篇自然语言仍用于视频 Prompt，但不能作为唯一连续性依据。每条 `shots[]` 必须包含：

```json
{
  "continuity": {
    "transition_from_previous": "continuous",
    "state_in": {
      "CHAR-001.location": "公交车西侧地面",
      "CHAR-001.pose": "半蹲",
      "CHAR-001.facing": "东",
      "CHAR-001.left_hand": "空手，贴近胸前",
      "CHAR-001.right_hand": "握持 PROP-001",
      "PROP-001.owner": "CHAR-001",
      "PROP-001.state": "完整",
      "bus.door": "关闭"
    },
    "state_out": {
      "CHAR-001.location": "公交车车顶中央",
      "CHAR-001.pose": "双脚站稳",
      "CHAR-001.facing": "北",
      "CHAR-001.left_hand": "扶住车顶边缘",
      "CHAR-001.right_hand": "握持 PROP-001",
      "PROP-001.owner": "CHAR-001",
      "PROP-001.state": "完整",
      "bus.door": "关闭"
    }
  }
}
```

`transition_from_previous` 只能是：

- `start`：第一条素材。
- `continuous`：与上一素材同一连续时间；当前 `state_in` 必须逐键等于上一素材 `state_out`。
- `cut`：同一时间线的有意省略或换地点；必须有剧本依据，并在 `transition_reason` 说明省略了什么。不可用来掩盖关键动作。
- `time_jump`：明确时间跳跃；必须在 `transition_reason` 写出时间变化。

事实表只记录跨幕仍可能影响后续的状态，不要记录光线颗粒、瞬时表情或无关背景细节。使用稳定、可重复的键名；同一实体跨素材不得换同义词。以下情况出现时必须建键：

- 人物位置、姿态、朝向、视线会影响下一动作；
- 左右手、道具归属或物理连接；
- 穿戴、伤势或能力状态发生变化；
- 门窗、车辆、机关、UI 等交互状态；
- 人数、队形或关键成员状态发生变化。

机位不进入事实相等性比较，放在 `spatial_state` 和运镜字段中。桥接动作必须让 `state_in` 可见地变为 `state_out`；不得只改账本而不在 `acts[]` 中拍出变化。

## 战斗：动作节拍

只有实际攻击、闪避、格挡、擒拿或解除威胁的幕才添加 `combat`。威胁对峙、奔跑或普通跌倒不强制添加。

```json
{
  "combat": {
    "beat": "attack",
    "actors": [
      "CHAR-001",
      "CHAR-002"
    ],
    "setup": "两人相距约1.5米，CHAR-001在左，CHAR-002在右",
    "intent": "CHAR-001试图用钢管迫使CHAR-002后退，为自己打开通路",
    "action": "CHAR-001从右侧向左横扫钢管；右手握持关系影响连续性，因此明确右手",
    "response": "CHAR-002后撤上身并向右跨步避让",
    "outcome": "钢管从CHAR-002胸前擦过，未命中；后撤使通路短暂打开",
    "recovery": "CHAR-001收回钢管停在身体右侧；双方相距约2米"
  }
}
```

六个语义环节必须完整：局面 `setup`、目的 `intent`、可见动作 `action`、对方应对 `response`、命中/落空及原因 `outcome`、可继承收势 `recovery`。

`combat` 描述单个 `act` 的局部因果；整条战斗素材的多轮编舞由 [10秒打戏 PREVIS](action-previs-10s.md) 中的 `action_design` 管理。禁止把同一份笼统 `combat` 复制到所有 `acts[]`。每个战斗幕只记录该时间段真正发生的攻击、应对和结果。

不要为满足模板机械添加生物力学细节。脚步、重心、左右手、握法仅在以下情况下强制明确：它决定命中/落空、道具归属、下一动作起点或跨素材连续性。攻击轨迹和接触/落空结果始终明确。

一幕只承担一个战斗节拍。组合技若无法在当前时长中清楚呈现每次接触和反应，就拆幕；不必把每一次细小肢体调整写成独立攻击。敌人可以因为眩晕、受困、视线遮挡或动作惯性暂时无法反击，但原因必须进入 `outcome`。

运镜必须让动作轨迹、关键接触或明确落空、主要反应可见。允许在完成结果和必要收势后切镜；不要求镜头无意义地停留到所有人完全静止。

## 校验

1. 第一条素材必须为 `start`；后续默认 `continuous`。
2. `continuous` 时逐键比较上一条 `state_out` 与当前 `state_in`；键集合和值都必须一致。
3. `cut/time_jump` 必须有 `transition_reason`，且不能跳过剧情关键桥接动作。
4. 每个 `state_in → state_out` 的变化必须能在本素材 `acts[]` 中找到可见原因。
5. 识别到实际战斗动作时必须有 `combat`，六个语义字段非空，`actors` 至少两项。
6. `combat.recovery` 与本幕结束以及素材 `state_out` 不得冲突。
7. 上一素材 `state_out` 中仍在场的角色、敌人或群体，下一素材不得因 `cut/time_jump` 或换场而无故消失。离场、逃走、死亡、失能、封印或消散必须在前一素材的可见动作、对应 `<ID>.status` 事实键和 `continuity.exit_state` 中记录，退场字段见 [动画导演字段](animation-direction.md)；“趁机进入”“省略过程”不能代替威胁解决。
8. 场景变化如果本身是剧情动作（穿门、进殿、登车、下楼），默认使用 `continuous` 并拍出桥接过程。只有不影响剧情因果的路程才允许 `cut`。
