# 工业级短剧生产协议

本协议是 `duanju` 的执行总线。它把剧本、资产、空间连续性、镜头和 MiniMax H3 Prompt 分成可以独立审计的层，避免一条提示词同时承担所有事实。

这里的默认媒介与时长用于新建创作；只转换既有数据时保留来源参数。H3 编译段仅在目标为 MiniMax H3 时执行。客户端导入与外部工具是否可用，见 [接入说明](client-integration.md)。

## 单一事实源

事实只允许在一个层级定义一次：

| 层级 | 负责内容 | 不负责内容 |
|---|---|---|
| `style` | 媒介、整体审美、画质、公共负向 | 人物姓名、临时动作、镜头路径 |
| `consistency.characters` | 人物/生物身份、外貌、服装、物种和不可漂移特征；Q版变体与本体的 `variant_of` 关系 | 剧情表演、镜头状态 |
| `consistency.scenes` | 场景几何、固定地标、基础光位 | 临时天气、粒子、UI、运镜 |
| `consistency.props` | 道具结构、材质、持有者和持续范围 | 属性数字、后期文字 |
| `shots[].continuity` | 00:00 与结束状态、位置、姿态、持物、出入场 | 风格改写 |
| `shots[].acts` | 可见动作、反应、对白、声音、镜头节拍；Q版 `inner_action` 与内心声时间事件 | 新造外貌事实 |
| `shots[].generation` | H3 模式、上传顺序、官方字段和可提交 Prompt | 新增剧情事实 |

冲突处理顺序固定为：用户本轮明确要求 → 当前剧本明确事实 → 已确认的一致性卡 → 风格锚点 → 通用预设。不能用风格预设覆盖角色卡事实。

## 六段生产管线

### 1. 输入契约

先识别用户给的是完整剧本、分场、已有分镜、角色提示词、已有 JSON 还是修改要求。未知剧情与身份事实只补齐能从文本稳定推导的内容；无法推导的内容进入 `open_questions` 内部清单，不把猜测直接写进角色实体。未指定服装属于可主动完成的美术设计空间，按 [人物提示词编排器](character-prompt-style.md) 先设计并记录到人物卡，区分美术补足与原文事实。

默认画面路线为“高精度3D写实国漫”。除非用户明确要求真人媒介，否则人物、场景、道具和视频 Prompt 均使用动画 CG 语义。

### 2. 资产编译

先分离人物、非人单体、固定群体、场景、道具和声音，再分配稳定 ID。每个人物、场景和道具资产生成完整参考图提示词，并按资产类型记录身份锁；音频资产记录声线卡，不要求生成图片；临时状态写入 `costume_states`、`state_delta` 或镜头账本，不污染基础身份图。

场景与道具不止提取品类名称：按 [场景与道具设计定稿](environment-prop-design.md) 补齐未指定的美术设计，在卡片中区分原文约束与设计补足，再生成参考图。美术补足不得新增剧情功能或改变关键空间关系。

用户要求内心戏时，按 [3D Q版内心戏](inner-theater.md) 将Q版作为独立人物变体资产；现实层、叠加锚点、内心声与退场必须在同一状态链中编译和校验。

人类单体必须保留用户指定的四视图锁定块。非人单体使用单一画面全身生物设定图，展开剪影、头部、材质、四肢、爪和尾部；不要把人类模板套给巨兽。

### 3. 状态图编译

把每个 10 秒素材先写成状态图，再写画面文字：

`state_in → beat_1 → beat_2 … → state_out`

每个变化必须说明触发、可见动作、结果和下一状态。进门、出门、起身、转身、拾取、放下、换手、换装、上下车和退场必须有桥接动作。只要状态变了，就同步改 `spatial_state`、`end_state`、`continuity` 和相邻素材。

### 4. 镜头编译

`camera_plan` 决定素材级轴线、模式和开场机位；`camera_motion` 决定幕级机位的起点、终点、运动类型、速度、幅度、目标和目的。`acts[].camera` 与导演时间线、最终 H3 Prompt 全部由 `camera_motion` 派生，不允许手写三份互相不同的运镜。

自然节拍不等于硬切。只有 `cut_before=true` 才生成新的 `[Shot N]`；连续镜头内保留同一摄影机路径。变焦只改变焦距，机身推进才改变位置；固定镜头不能改变机位、视轴或焦距。

### 5. H3 编译

先选模式，再绑定上传文件：

- 没有上传素材：`T2VA`。
- 只有首帧：`I2VA`。
- 首尾帧：`FL2VA`。
- 只有尾帧：`L2VA`。
- 人物/场景/道具/视频/音频作为参考：`Ref2VA`。

身份参考不能冒充首帧；首尾帧不能混入 `reference_order`。上传标签按稳定顺序生成，不能在 `subject_definitions`、`summary`、`retention_analysis` 和 `detailed_description` 中改名。

每个 `acts[].time` 都要编译成 `From HH:MM.mmm to HH:MM.mmm` 的节拍区间；时间区间只控制动作节拍，不自动制造硬切。

### 6. 质量门禁

交付前必须通过：JSON 结构、稳定 ID、资产引用、时长与时间码、状态连续性、桥接动作、动作因果、配音预算、运镜同步、H3 字段顺序、参考素材上限、Prompt 长度、媒介负向和角色资产类型检查。新项目启用 `design_contract: "duanju_design_v1"` 后，还必须通过服装/场景/道具设计完整性门禁；绑定本地素材时检查路径存在；外部工具的 `--verify-media` 使用边界见 [客户端接入说明](client-integration.md)。任何 `E` 级错误都不能交付；修复后必须全量复检。

## H3 硬上限

- 时长：4–15 秒整数；默认 10 秒。
- Prompt：不超过 7000 字符。
- 图片：最多 9 张；视频最多 3 段；音频最多 3 段；三类合计最多 12 个。
- 图片宽高比：0.4–2.5；图片边长：256–5760 px。

## 修复优先级

按“模式/素材 → 状态链 → 动作因果 → 镜头 → 音频 → 文案压缩”的顺序修复。不要先压缩 Prompt 来掩盖状态错误；不要删减剧本台词、面板字段或结果来规避时长问题。放不下时拆成新的 10 秒素材。
