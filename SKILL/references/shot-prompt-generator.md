# 逐幕分镜脚本生成器（第三步）

把**剧本片段**（分场文字 / 小说式剧本 / 剧情大纲）转换成内部逐幕分镜结构：一个动画素材对应最终 JSON 的一条 `shots[]`，内部按幕切分，每幕带 **时间码 + 画面 + 运镜 + 音效/配音**。默认生成 10 秒素材；MiniMax H3 目标允许用户明确指定 4–15 秒整数。Markdown 模板仅作为内部组装规范，默认不向用户展示。

> 核心工作流：**剧本片段 + 第一步公共视觉词 + 第二步一致性卡 → 分镜脚本 → 逐幕生成**。公共视觉词（含负向锚点）与人物/场景/道具/音频卡在**生成时**拼装到各幕提示词前缀，分镜正文保持干净：不写人物外貌、不写公共视觉词、不写负向锚点。

> 前置输入：剧本片段（或已有分镜表）+ 第一步公共视觉词 + 第二步四张一致性卡（人物/场景/道具/音频）。

## 时长选择硬规则

1. 用户没有说明单素材时长时，始终使用 **10 秒**。
2. 目标为 MiniMax H3 时，接受用户明确指定的 **4–15 秒整数**；其他目标保持原有平台支持的时长。
3. 不得因为内容是觉醒、打斗、高潮或台词较长而自行升级为 15 秒；内容放不下时，拆成多个 10 秒素材。
4. 用户同时提到两种时长没有明确选择时，仍以 10 秒为默认值。
5. 每个素材最后时间码必须准确结束在该素材的 `duration_s`，例如8秒素材结束在 `00:08`。

对白、悬疑、情绪和操作戏按 [文戏导演与时间管理](drama-editing.md) 组织，不能套用战斗密度。每幕写 `- **动作类型：** dialogue` 等明确类型。限时剧情按该文档记录故事时钟与剪辑区间。

若素材含Q版内心戏，每幕另写 `**Q版动作：** {单行JSON}`；素材顶部写 `**内心戏：** {单行JSON}`，第一人称写 `**第一人称人物：** CHAR-###`。声音事件必须带 `channel`、`audio_id`、`lip_sync_target`、`time` 和可选 `pause_after_s`，具体字段见 [3D Q版内心戏](inner-theater.md)。

## 连续状态链（先于素材拆分）

详细数据结构和校验规则见 [连续性账本与战斗节拍](continuity-combat.md)。本节只规定分镜编排顺序。

1. 先按剧本顺序列出所有会改变画面状态的动作及其结果，再划分素材边界；不得先分别写完各素材，再用静态描述掩盖中间缺失动作。
2. 每个动作节点至少核对：人物所在位置、站/坐/蹲/卧/腾空姿态、身体朝向、视线、左右手、持有道具、穿戴装备、伤势、门窗与车辆等交互物状态、UI显示状态。
3. 素材边界必须落在一个确定可描述的状态上。边界前写入素材N的 `end_state`，同一物理状态展开为素材N+1的 `spatial_state`；只允许机位重新选择。
4. 如果剧情从“林风在地面”变成“林风在公交车顶”，状态链中必须存在“奔向公交车—攀爬或跳上车顶—在车顶站稳/蹲稳”。缺少任一必要动作时，调整相邻素材时间分配或新增10秒素材。
5. 全部分镜完成后执行两遍审计：第一遍检查每个素材内部 `spatial_state → acts → end_state` 是否自洽；第二遍逐对检查 `shot[N].end_state → shot[N+1].spatial_state` 是否存在瞬移、凭空换装、道具换手、姿态跳变或交互物状态跳变。发现问题必须改分镜，不得标注“可能不连贯”后保留。

## 一、分镜脚本格式（标准模板）

```markdown
### **《剧名》10秒动画脚本**

**一致性引用：** 呱比参考 {{CHAR-001}}，蓝色甲虫参考 {{CHAR-002}}，森林场景参考 {{SCENE-001}}，黑色塑料袋面罩道具参考 {{PROP-001}}，呱比声线参考 {{AUDIO-001}}

**空间状态锁定：** 用完整具体句子展开人物站位、姿态、朝向、视线、左右手、道具位置与角度、UI占位、环境位置、机位、镜头高度和构图。

**连续性模式：** start

**开场事实：** {"CHAR-001.location":"明确位置","CHAR-001.pose":"明确姿态","PROP-001.owner":"CHAR-001"}

**结束事实：** {"CHAR-001.location":"动作后的明确位置","CHAR-001.pose":"动作后的明确姿态","PROP-001.owner":"CHAR-001"}

**退场状态：** {}

**风险等级：** standard

**镜头钩子：** {"type":"setup","payoff":"本镜兑现的信息或情绪","next_hook":"下一镜期待"}

**动作设计：** 仅战斗镜头填写 `action_design` 单行标准 JSON；普通镜头省略。

**⏱️ 00:00 - 00:02 | 第一幕：幕名**

- **画面：** 详细动作画面描写——谁、做什么、动作怎么发生、表情/细节如何变化。
- **运镜：** 景别切换/运镜术语 + 效果描述。
- **战斗节拍：** 仅实际战斗幕填写单行标准 JSON；普通幕省略。
- **表演曲线：** 高风险镜头每幕填写单行标准 JSON，字段见 [动画导演字段](animation-direction.md)。
- **音效/配音：**
  - 拟声/音效描述："拟声"
  - 角色配音（语气标注）："台词"

**⏱️ 00:02 - 00:04 | 第二幕：幕名**

- **画面：** …
- **运镜：** …
- **音效/配音：**
  - …

**结束状态锁定：** 用完整具体句子描述最后一幕结束时人物、道具、装备、环境交互物和UI的确定可见状态，供下一素材校验。

**导演时间线：** 仅高风险镜头填写 JSON 数组，按自然动作节拍完整覆盖本素材时长，并与各幕使用相同时间边界；普通镜头省略。
```

### 格式规则

- **标题行**：`### **《剧名》N秒动画脚本**`。N 默认取 10；MiniMax H3 可按用户明确要求取 4–15 的任一整数。一个标题块 = 一个生成素材；一部片有多个素材时，每个素材一个标题块。
- **幕头**：`**⏱️ 开始 - 结束 | 第X幕：幕名**`。幕名一句话概括本幕事件（如"警觉的'忍者'"）；幕号连续（第一幕、第二幕……）。
- **时间码**：从 00:00 起**连续递增、不重叠、不跳段**。普通剧情每幕通常 2–4 秒；战斗镜头按动作量使用 4–7 个自然节拍，每段通常 0.5–3 秒。
- **一致性引用位置**：每个素材只输出一次，紧跟标题并置于第一幕之前。汇总该素材所有幕会用到的人物、场景、道具和固定声线素材；各幕内部禁止重复显示。
- **结束状态锁定**：每个素材最后一幕后必须输出一次。它不是尾帧图片提示词，而是下一素材的连续性事实表；必须写明最后一刻的人物位置、姿态、朝向、视线、左右手、持有道具、穿戴装备、伤势、门窗或车辆等交互物状态和仍在显示的UI。JSON 映射为 `end_state`。
- **结构化事实账本**：`连续性模式 / 开场事实 / 结束事实` 紧跟空间状态。事实使用单行标准 JSON，键名跨素材保持不变；详细规范见 [连续性账本与战斗节拍](continuity-combat.md)。
- **导演字段**：`退场状态 / 风险等级 / 镜头钩子 / 表演曲线 / 导演时间线` 按 [动画导演字段](animation-direction.md) 输出。`risk_level: high` 时不得省略表演曲线和导演时间线。
- **相邻素材交接校验**：除明确时间跳跃或转场外，素材N的 `end_state` 与素材N+1的 `spatial_state` 必须在物理状态上逐项相等。机位允许变化，但下一素材必须完整描述新机位。若人物位置、姿态或道具状态不同，必须在两段之间安排可见桥接动作，不得直接改写静态状态。
- **禁止分类占位**：不要输出 `人物：CHAR-001；场景：SCENE-001` 这类脱离名称的分类编号列表，也不要只写“人物参考/场景参考/道具参考”；必须写明具体名称，并用双花括号包裹对应稳定 ID。
- **汇总范围**：任一资产只要在该素材的某一幕使用，就必须列在顶部；重复使用只列一次，没有任何绑定时写 `无`。
- **三要素缺一不可**：每幕必须有 `画面 / 运镜 / 音效-配音` 三段，顺序固定，缺一段不成幕。
- **正文干净**：分镜正文不写公共视觉词、不写人物外貌/服装（引用一致性卡）、不写负向锚点；这些在生成时拼装（见"生成时拼装规则"）。

## 二、画面 / 运镜 / 音效写作语法

### 画面段（每幕核心）

1. **明确主语**：多人交互、切换主语或跨素材开场使用人物卡固定称谓（如“呱比”“甲虫”）；避免可能指向多个角色的代词。
2. **一幕一主动作**：每幕只写一个核心动作，可带 1–2 个细节副动作，写太多 AI 会混淆。动作描述要具体有画面感（示例："头猛地向右歪去，粉色大舌头随着惯性甩了一下"）。
3. **固定词序**：`谁 → 做什么 → 动作细节 → 表情/状态变化`。词序越稳定出片越稳。
4. **独立素材起始状态**：每个素材从 `00:00` 独立生成。第一幕首句须与顶部空间状态一致，再写新增动作，不重复整段人物或环境描述；已经完成的动作不得重新执行。
5. **禁止外部指代**：最终分镜禁止写“承接上一素材”“延续上一镜”“保持上一画面”“继续刚才动作”等生成模型无法读取的关系词。内部可以读取前一素材结束状态，但必须将其展开为本素材独立可生成的开场描述。
6. **桥接动作不可省略**：爬上、跳下、进入、离开、翻窗、转身、起身、蹲下、拾取、放下、换手、换装、开门、关门、上车和下车等改变连续状态的动作必须实际出现在某一幕。若上一素材结束时人物在地面、下一素材需要人物在车顶，就必须先拍摄攀爬或跳上车顶，不能直接把下一素材开场写成已经在车顶。内容放不下时新增一个10秒素材。
7. **素材内部状态一致**：顶部 `spatial_state`、第一幕第一句必须描述同一个00:00状态；顶部不得写“已经腾空”而第一幕又写“站在车顶”。最后一幕最后一刻必须与 `end_state` 一致。
8. **写完整动作，不写无关静止信息**：画面段负责动态；人物长相和场景材质归一致性卡，不重复堆砌。与空间连续性有关的站位、姿态、左右手、道具、UI和机位必须在空间状态及第一幕复写。
9. **动态特效按幕添加**：数据光、能量、粒子、UI、HUD、血条、光屏和数据框只写进实际出现的幕，不得反向写入公共视觉词、人物卡、场景卡或道具卡。需要准确文字、数字、图标或属性面板时，在画面段明确标注“后期叠加”，不要让视频模型直接生成文字。
10. **时长两档**：
   - **10 秒（默认，普通剧情）**：一幕一主动作 + 单一运镜（推/移/甩/固定），内容超出时继续拆成下一个 10 秒素材。
   - **10 秒战斗**：不套用普通剧情的“整条素材一个主动作”限制；按 [10 秒打戏 PREVIS](action-previs-10s.md) 先建立两轮攻防，再切成自然节拍。
   - **15 秒（仅用户明确指定）**：动作 + 反应两拍（如"扭头警觉 → 表情变化"）+ 运镜完整弧线（推近→停顿→揭示）。

### 战斗动作专用规则

实际攻击、闪避、格挡、擒拿或解除威胁的幕，按 [连续性账本与战斗节拍](continuity-combat.md) 添加 `combat`。画面正文只保留模型需要看见的动作因果，不机械堆砌每一只脚、每一次重心变化。伤害数字和血条变化只能在动作结果之后作为后期叠加，不能替代接触、落空和反应。

### 运镜段

H3 优先执行 [运镜规划](camera-h3.md)：连续路径先记录 camera_motion，再编译 camera。以下通用示例不能覆盖 H3 的单镜/切镜模式。

11. **用术语**：景别/运镜/角度/构图一律用词汇库标准术语（中英对照），不用口语描述；先判断是机身前移还是焦距改变，不能把含糊的“靠近”直接判成变焦。
12. **运镜 = 景别切换/运镜术语 + 效果描述**：如"机身不移动，从中景快速变焦至特写，快速变焦推近（Crash Zoom），瞬间怼到脸上，背景微动态模糊"。
13. **一幕一主运镜**：主运镜一个，可带一个节奏变化；特殊效果（慢镜头/升格）写在这里。

### 音效/配音段

14. **配音统一引用**：角色配音、系统音、旁白等**全剧固定音色**，逐幕只写"角色配音（语气标注）：台词"，音色/语速/语气引用第二步角色音频卡，不逐幕重写。
15. **声音必须有来源**：只保留以下声音：剧本明确写出的声音/台词；画面中可见动作直接产生且确有必要的物理声音；按下、弹出、切换等明确 UI 交互对应的电子反馈音。禁止为了烘托情绪擅自添加心跳、呼吸、鼓点、提示音、空槽音或其他拟声；静止显示、空槽停留、面板文字出现本身不自动产生声音。不得把没有声源依据的内容写成“咚”“砰”“滴”等拟声。
16. **面板显示与播报分离**：系统面板、属性面板、HUD 或数据框中承担剧情信息的文字与数值，除非用户明确要求静默展示，否则按显示顺序使用系统配音自然播报。画面段必须以“后期叠加”保留原始界面文字；音频段保存适合口语的播报文本，禁止机械朗读斜杠、连字符、括号或界面符号。
17. **数值播报规范**：`当前值/上限值` 型进度数值默认只播报当前值，画面仍显示完整原文，例如 `血量：100/100 → 血量：100`、`蓝量：150/150 → 蓝量：150`、`经验：0/100 → 经验：0`、`HP：80/80 → 生命值：80`、`耐久：20/20 → 耐久：20`；只有用户或剧情明确要求说明上限时才自然播报“当前值……，上限……”。数值区间 `3-5` 播报为“3到5”。不得改变任何实际数值。
18. **面板朗读与显示同步**：仅在剧本或用户明确要求朗读时，依次播报本幕实际显示或高亮的字段，不提前播报。只要求显示的文字保留在 `visual`，不能自动增加配音；纯装饰图标、边框和无文字光效不朗读。
19. **配音时长预算**：按自然中文配音每秒最多约4.5个可读字符估算；汉字、数字和英文词均计入，标点不计。若同一幕还有咆哮、碰撞或关键动作音效，先为音效至少预留0.5秒，再计算可用配音时长。超过预算必须精简为不丢信息的自然播报、延长该幕或拆到后续素材；禁止让长系统播报覆盖撞击、咆哮或人物台词。
20. **音效逐幕列出**：本幕有来源的拟声逐条列出（如剧本明确写出塑料袋摩擦，或画面出现钢管落地）。BGM 若全剧统一则不重复写，特殊变化（节奏加速/爆发）才标注。
21. **允许无声**：若本幕没有符合来源规则的音效、台词或系统朗读，保留 `音效/配音` 段并写 `- 无额外音效/配音。`，不得为填满格式而编造声音。
22. **条目格式**：`- 描述："拟声/台词"`。拟声用引号括起；配音条目在角色名后括注语气。系统播报格式为 `- 系统配音（客观播报）："自然播报文本"`。

### 生成时拼装规则（不进分镜正文）

- 引用本素材实际使用的人物、场景、道具和音频资产。正式资产决定外观；`spatial_state`、`continuity` 和逐幕动作决定空间与交接，详细要求见 [连续性账本](continuity-combat.md)。

- 内部分镜稿与最终 H3 Prompt 分工不同：分镜稿保存导演事实，H3 Prompt 保存模型执行指令。编译时必须遵循 [H3 工业级提示词契约](h3-prompt-contract.md)，不能把下面的中文规则直接拼成一段无字段的大提示词。
- 先按实际输入选择 `T2VA / I2VA / FL2VA / L2VA / Ref2VA`，再组装 Prompt。人物、场景、道具参考图属于身份/外观输入；首帧和尾帧属于时间锚点，不能混用。
- Base 模式固定输出 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`；Ref2VA 固定输出 `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。
- 逐幕变化段 = **公共视觉路线 + 本幕实际出现的资产职责 + 空间状态 + 画面动作 + 派生运镜 + 有声源的声音**。不要因为编号列在顶部就强制让该资产出现在每一幕；不要把完整人物提示词重复塞进每条视频 Prompt。
- 配音流程从顶部 `AUDIO-###` 集合中选择本幕音效/配音段实际点名的角色；环境音效和拟声不编号。
- 人物/场景/道具描述一律从第二步一致性卡引用，禁止在分镜中改写人物外貌。
- 公共视觉词**一字不改**，分镜正文（画面/运镜）即"该镜头变化段"，变化段只写在尾部，不得改动词根本身。
- H3 的正文结构字段使用英文；中文对白、角色专名和画面可见文字按原文保留。对白用稳定 `(S1)` 声源和 `<d>[Chinese] ...</d>`，画面文字使用英文双引号包裹并逐字保留。
- `overall_soundscape` 只总结环境声和动作声；`non_diegetic_music` 只写观众侧配乐；没有配乐写 `N/A`，不要把对白复制到两个音频字段。
- 支持"角色参考图"的工具（可灵、即梦）：人物卡词与参考图同时使用，两者不得冲突。
- 若工具需要首帧定帧图：从该幕"画面"段提取静态定格描述（去掉动作，只留那一刻的人物/场景/构图）作为首帧提示词，不必写进分镜正文。

## 四、时长两档内容密度

| 时长 | 适用 | 画面拍数 | 运镜 |
|------|------|---------|------|
| **10s普通剧情（默认）** | 非战斗内容 | 1 个主动作 | 单一主运镜（推/移/甩/固定） |
| **10s战斗** | 实际攻击、格挡、闪避、擒拿或追击 | R1至少1轮、R2/R3至少2轮攻防 | 4–7个自然节拍，镜头变化服从动作可读性 |
| **15s（需明确指定）** | 仅用户明确要求的 15 秒素材 | 动作 + 反应两拍 | 完整弧线（推近→停顿→揭示/切换） |

> 10s/15s 是**单素材生成时长**。默认将长内容拆成多个 10 秒素材，不自行改成 15 秒；每幕 2–4 秒是素材内部的节拍划分。

第三步内部完成后，必须把每个素材直接映射为 `shots[]`，把一致性引用映射为 `references[]`，把空间状态锁定映射为 `spatial_state`，把结束状态锁定映射为 `end_state`，把每幕映射为 `acts[]`；字段结构见 [json-schema.md](json-schema.md)。默认不展示 Markdown 分镜正文；当前格式不输出废弃的 `assets`、`tail_frame` 或工具槽位字段。

## 五、分镜写法示例：《呱比的猎物》10秒动画脚本

以下示例展示逐幕写法，不是满足 Schema 2.6 全部字段的可提交项目；正式输出须补齐资产、连续性、导演字段及目标模型配置。

### **《呱比的猎物》10秒动画脚本**

此为用户明确要求剪辑式片段时的通用示例；H3 输出还需填写 camera_plan 和各幕 camera_motion，并从切点派生 Shot 标记。

**一致性引用：** 呱比参考 {{CHAR-001}}，蓝色甲虫参考 {{CHAR-002}}，森林场景参考 {{SCENE-001}}，黑色塑料袋面罩参考 {{PROP-001}}，蓝莓参考 {{PROP-002}}，呱比声线参考 {{AUDIO-001}}，蓝色甲虫声线参考 {{AUDIO-002}}


**空间状态锁定：** 呱比位于森林空地中央，身体面向画面右侧，双脚落地，头部正对右前方；黑色塑料袋面罩戴在头部。蓝色甲虫位于画面外右侧。摄像机位于呱比正前方约2米、距地面0.8米，中景平视，呱比处于画面中央。

**⏱️ 00:00 - 00:02 | 第一幕：警觉的"忍者"**

- **画面：** 呱比正骄傲地戴着他的黑色塑料袋面罩。突然，他察觉到画外异响。他的头猛地向右歪去，粉色的大舌头随着惯性甩了一下。
- **运镜：** 机身固定，从中景变焦到特写。**快速变焦推近（Crash Zoom）**，瞬间怼到呱比呆萌且斗鸡眼的脸上，背景产生微弱的动态模糊。
- **音效/配音：**
  - 塑料袋摩擦的清脆声："哗啦—"
  - 头部转动的弹簧拟音："Boing！"
  - 舌头甩动的湿润声："啪嗒。"
  - 呱比配音（短促、鼻音重、上扬的疑问语气）：*"呱？"*

**⏱️ 00:02 - 00:04 | 第二幕：苦力的路过**

- **画面：** 镜头切到低角度。蓝色甲虫正迈着六条小短腿，极其吃力地背着一颗比它还大的蓝莓，像举重运动员一样，飞速从画面右侧向左侧狂奔。
- **运镜：** 贴地低视角。**快速横移跟拍（Tracking Shot）**，紧紧咬住甲虫的移动轨迹，强调它步伐的紧凑感。
- **音效/配音：**
  - 极其密集且清脆的小虫子碎步声："提里提里提里提里！"
  - 甲虫配音（闷声闷气、吃力的搬砖音）：*"叽哩！叽…叽哩！"*

**⏱️ 00:04 - 00:07 | 第三幕：猫系伪装者**

- **画面：** 呱比瞬间警惕，身体"啪"地趴在地上。他像准备扑击的猫一样，屁股高高撅起，极其夸张地左右扭动蓄力，然后化作一道绿色的残影，迅速窜到右侧的大树后。
- **运镜：** **手持感镜头（Handheld）**。镜头随着呱比扭屁股的频率微微上下震动，接着一个**极速甩镜头（Whip Pan）**向右，捕捉他躲到树后的瞬间。
- **音效/配音：**
  - 趴下的音效："吧唧！"
  - 扭屁股的音效：类似搓气球的"叽咕、叽咕、叽咕"声。
  - 冲刺音效："嗖——"
  - 呱比配音（压低的、奶凶的蓄力声）：*"嗯……呱！"*

**⏱️ 00:07 - 00:10 | 第四幕：极限走位**

- **画面：** 呱比从右侧树后探出半个脑袋，左右看了一下。接着，他开启"忍者模式"，用极其夸张的"Z"字形走位，左右腾挪，闪现出残影，咻的一下到了左前方离甲虫必经之路更近的一棵大树后。
- **运镜：** **跟随拉片镜头（Dolly Out + Pan）**。镜头始终保持呱比在画面中央，背景的树林因为他快速的左右横跳产生强烈的速度线模糊。
- **音效/配音：**
  - 探头时的音效："啵！"（类似拔瓶塞）。
  - Z字闪现的音效："咻咻咻"。
  - 呱比配音（急促、弹性的喘息）：*"呱！比！比！比！"*

**结束状态锁定：** 呱比位于左前方大树后，身体贴近树干并面向甲虫必经路线，黑色塑料袋面罩仍戴在头部；蓝色甲虫仍背着蓝莓沿地面向左移动；摄像机停在树林中景。

> 示例说明：以上为一整段完整的 10 秒素材，时间码从 `00:00` 连续覆盖到 `00:10`，三要素齐全。

## 六、校验清单（每幕定稿前自查）

- [ ] H3 的 camera_plan 与每幕 camera_motion 完整；连续段和跨素材 match 机位相等，派生 camera 已进入 Prompt
- [ ] H3 的推拉、变焦、摇镜和横移没有混用；Shot 编号只标记实际切镜
- [ ] H3 `generation.h3_mode` 与 `generation.mode`、上传素材类型一致；Prompt 字段顺序符合 H3 工业级提示词契约
- [ ] Ref2VA 的六个字段顺序固定，参考标签在定义、保留分析和详细时间线中含义一致
- [ ] I2VA/FL2VA/L2VA 的对齐指令位于 Prompt 首行；首镜不带时间戳，后续硬切使用严格递增的 `At MM:SS.mmm`
- [ ] Prompt 中的对白使用稳定 `(Sx)` 和 `<d>[语言] 原文</d>`；可见文字保留原文；环境声与配乐不重复对白
- [ ] 每条 Prompt 不超过7000字符；重复人物身份词放在一致性资产，视频 Prompt 只保留当前动作所需的可见身份锚点

- [ ] 标题行：`### **《剧名》N秒动画脚本**`；新建创作默认 N = 10，H3 接受用户指定的 4–15 秒整数，其他模型遵守其支持范围
- [ ] 未明确指定其他时长时使用 10 秒；内容超出时拆成多个素材，不擅自加长
- [ ] 最后一幕必须准确结束在当前素材的 `duration_s`，默认 `00:10`
- [ ] 幕头：`**⏱️ HH:MM - HH:MM | 第X幕：幕名**`，时间码连续递增、不重叠
- [ ] 每个素材标题下方、第一幕之前仅输出一次一致性引用，汇总全部幕使用的具体名称与稳定 ID
- [ ] 空间状态和第一幕没有“承接上一素材/延续上一镜/保持之前/继续刚才”等外部指代
- [ ] 每个素材都有 `end_state`；最后一幕最后一刻与 `end_state` 完全一致
- [ ] 每个素材都有非空 `continuity.state_in/state_out`；`continuous` 时与上一素材逐键一致
- [ ] 除明确转场外，上一素材 `end_state` 与下一素材 `spatial_state` 的人物、姿态、朝向、左右手、道具、装备、伤势和交互物状态逐项连续
- [ ] 攀爬、上下车、进出门窗、转身、起身、蹲下、拾取、放下、换手和换装等状态变化均有可见桥接动作，没有人物或道具瞬移
- [ ] `spatial_state`和第一幕第一句是同一个00:00状态，没有用中途或结尾高潮姿势充当开场状态
- [ ] 各幕内部没有一致性引用行
- [ ] 没有 `人物：CHAR-001` 这类内部分类编号列表
- [ ] 三要素齐全：画面 / 运镜 / 音效-配音，顺序固定
- [ ] 画面一幕一主动作（10s）或动作+反应（15s），主语用人物卡称谓，无"他/她/男主"类代词
- [ ] 有Q版内心戏时，现实层先写清楚，Q版单独写锚点、相对尺寸、遮挡、光线和观众可见规则；Q版动作不改变摄影机，现实人物不对Q版作出反应
- [ ] 有Q版内心戏时，每幕都有连续的 `inner_action`；内心声引用 `inner_voice` 选定的本体或Q版专属音频，口型只指向Q版；最终Prompt明确Q版开口说原文、本体闭嘴，`time` 与 `pause_after_s` 不重叠且落在幕内
- [ ] 每个实际战斗幕都有 `combat`，完整表达局面、目的、动作、应对、结果和收势
- [ ] 脚步、重心、左右手只在影响命中、道具归属或下一状态时明确，没有模板化堆砌
- [ ] 2至4秒内没有三个独立伤害、多个换装/拾取/学习动作或无法形成单一因果链的动作堆叠
- [ ] 运镜用词汇库术语，一幕一主运镜，无口语化描述，无否定句
- [ ] 战斗运镜完整展示攻击轨迹、接触点、受击反应和收势，没有在接触前切走
- [ ] 配音只写角色名 + 台词 + 语气，音色引用角色音频卡不重写
- [ ] 所有声音都有剧本、可见动作或明确交互依据；没有擅加心跳声、呼吸声、提示声、空槽音或无来源拟声
- [ ] 面板剧情信息按显示顺序由系统配音读出，文字与数值不漏项、不改写；长内容拆成后续 10 秒素材
- [ ] 配音不超过每秒约4.5个可读字符；同幕有关键音效时已预留至少0.5秒
- [ ] 静止面板和空槽本身没有强配提示音；无声音内容时明确写“无额外音效/配音”
- [ ] 音效逐幕列出；BGM 特殊变化才标注
- [ ] 分镜正文无公共视觉词/人物外貌/负向锚点（生成时拼装）
