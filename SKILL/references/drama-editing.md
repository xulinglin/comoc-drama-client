# 文戏导演与素材时间管理

对白、悬疑、情绪、救援或操作戏读取本文件；实质攻防另读战斗规则。10秒是默认生成素材长度，不是所有动作必须平均分成四幕，也不是故事时间的默认计时单位。

## 文戏按信息与选择分镜

每镜先确定观众本次看到的新信息，以及谁因此改变判断或行动。先写可见过程，再决定景别、运镜和切点。

- **对白**：先建立说话者与听者的空间关系。让视线、呼吸、停手或移开目光表现听者反应，不让双方全程面对镜头轮流报台词。台词按完整语意分配时间；长句可以跨动作节拍持续说完，不机械拆成每段等长的碎句。
- **悬疑**：安排线索进入视野的时机、可读停留和人物识别后的反应。遮挡与景深服务揭示，不提前显示尚未发现的名字、脸或终点信息。神秘感不能靠把画面全部压黑。
- **情绪选择**：用动作改变体现情绪转折，例如伸手后停住、松开已经抓紧的门边；给选择发生前后的姿态留出差异，不只标注“震惊→坚定”。
- **操作与救援**：先让操作面、手、受影响的机关与通行方向可读，再展示连接和结果。机械声只随实际动作发生；不把插卡、按键和开门都自动写成战斗。
- **镜头选择**：固定机位适合明确的对峙或精细操作；缓推用于缩小注意范围；空间揭示可用摇镜、横移或拉远。每次运动说明让观众看清什么，不默认所有镜头固定，也不为丰富而移动。

每幕 `action_type` 使用 `dialogue/reveal/interaction/movement/hold/combat` 之一。按本幕主要目的选择；只有真实攻防用 `combat`。高风险仍按动画导演规则填写表演曲线和导演时间线，但节拍按实际动作分配，不重复套用“预备—动作—结果—收势”文案。普通静态镜头不需要升级为高风险。

画面文字与对白分开：剧本要求显示的原文留在 `visual`；只有原文明确播报或已确定的声音交互才进入 `audio`。信息重要不代表必须朗读。`none` 表示没有额外声音，不能被编译成“保持安静”的画内音效。

## 三种时间明确区分

- `duration_s`：生成素材时长，默认10秒；只在用户明确要求时改为支持的其他整数。
- `timing.edit_range_s`：最终剪辑使用的素材区间，如 `[1,9]`，不能超出素材时长。未填写 `timing` 时默认使用全条素材。
- `timing.story_range_s`：素材首尾对应的故事时间，配合 `clock_id` 使用；是创作设定，不从字幕猜测。区间按素材时间线性映射，适用于实时或匀速慢放。变速、非线性跳时拆成素材或另行明确编辑方案，不能套用线性映射制造假精确。

有倒计时、限时机关、并行行动或明确时间跳跃时必须记录相关故事时钟；其他镜头无需强填。交叉剪辑可以共用同一故事区间，不能把两个并行镜头的时长相加当作故事流逝。未解决的原文时间冲突需要明确指出，不能靠增加素材或缩短读数掩盖。

每集汇总区分“生成素材总时长”与“剪辑选用总时长”；若片段包含重叠视点或重复展示，说明剪辑意图。结构校验只检查已提供的数据，缺少故事时间时不能声称倒计时已验证。

## 数据示例与校验

素材1：`"timing": {"edit_range_s": [0,10], "clock_id": "safety_gate", "story_range_s": [0,10]}`。
素材2：`"timing": {"edit_range_s": [0,10], "clock_id": "safety_gate", "story_range_s": [10,20]}`。

顶层记录可校验的规则事件：

```json
{
  "time_constraints": [
    {
      "label": "安全门开启12秒",
      "start": {"shot_id": 1, "clip_s": 3},
      "end": {"shot_id": 2, "clip_s": 5},
      "duration_s": 12
    }
  ]
}
```

以上事件分别落在故事时间3秒与15秒，差值12秒。`E024 STORY_TIME` 检查剪辑范围、故事区间、事件引用和时差；还需人工核对对应幕是否真的在指定时间开门/关门。Markdown项目以 `**时间管理：** {单行JSON}` 写入素材；跨素材 `time_constraints` 在最终项目JSON填写，再全量复核；已安装外部编译器时可使用其 `--compile-json`，工具边界见 [客户端接入说明](client-integration.md)。
