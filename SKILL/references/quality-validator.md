# 质量校验与自动修复

最终 JSON 只允许在全部阻断错误清零后输出。校验分为两级：结构检查包括 JSON 解析、字段、引用与时间关系；动作、衔接和画面语义按本文件复核。本仓库未附自动校验脚本，已安装外部校验器时再执行其检查，工具边界见 [客户端接入说明](client-integration.md)。警告也必须人工确认，不能直接忽略。

## 一、校验顺序

1. 先生成完整内部草稿，不向用户输出。
2. 执行确定性结构校验：JSON结构、稳定ID、引用存在性、时长、时间码覆盖、必填字段、音频类型和配音时长预算。
3. 执行素材内部语义校验：`continuity.state_in → acts → continuity.state_out`，并核对自然语言 `spatial_state/end_state`。
4. 执行相邻素材确定性校验：`continuous` 时逐键比较 `shot[N].continuity.state_out` 与 `shot[N+1].continuity.state_in`。
5. 执行战斗动作校验、开场空间状态校验、信息完整性校验和资产状态校验。
6. 有阻断错误时进入修复循环；错误清零后重新执行一次全量校验，确认没有因修复产生新的下游错误。

## 二、阻断错误代码

- `E001 JSON_STRUCTURE`：缺少顶层字段、字段类型错误或不是标准JSON。
- `E002 ID_REFERENCE`：稳定ID重复、前缀错误、引用不存在或引用类型不匹配。
- `E003 TIMECODE`：时间码不能解析、不从00:00开始、存在空档/重叠或没有准确结束在当前素材 `duration_s`。
- `E004 REQUIRED_FIELD`：素材缺少 `spatial_state`、`end_state`、幕画面、运镜或音频。
- `E005 INTERNAL_STATE`：`spatial_state`、第一幕第一句不是同一状态，或最后一幕与 `end_state` 不一致。
- `E006 HANDOFF_STATE`：`continuous` 素材的事实键集合或对应值与上一素材 `state_out` 不一致。
- `E007 MISSING_BRIDGE`：爬上、跳下、进出、翻窗、转身、起身、蹲下、拾取、放下、换手、换装、上下车等必要桥接动作没有进入任何一幕。
- `E009 ACTION_OVERLOAD`：2至4秒内存在多个不能形成单一连续因果链的主要动作；装备、拾取、学习或多次独立攻击被压缩在同一幕。
- `E010 COMBAT_CAUSALITY`：实际战斗幕缺少结构化 `combat`，或局面、目的、动作、应对、结果、收势任一语义环节缺失/互相冲突。
- `E011 CAMERA_CONTACT`：运镜在接触前切走、没有展示接触点或没有为受击反应与收势留时间。
- `E012 AUDIO_BUDGET`：配音超过该幕自然语速预算，或与咆哮、碰撞、人物台词争用同一时间而无法清楚听见。
- `E013 SCRIPT_OMISSION`：原剧本的动作、台词、面板字段、数值、掉落物或结果被遗漏、改值或提前出现。
- `E014 ASSET_STATE`：基础人物卡混入后续换装，关键道具持有者或持续范围错误，场景状态与剧情阶段冲突。
- `E015 CONTENT_SAFETY`：视频涉及丧尸、亡灵、变异怪物、尸化角色或近身伤害时，缺少视频所需非血腥约束；人物参考图不以固定13项词组作为通过条件；相关人物卡正向字段使用伤口、腐烂创面、裸露组织、骨骼、内脏、断肢或断头塑造角色；相关场景或道具提示词引入血迹、残肢或血腥尸堆。
- `E017 UNRESOLVED_EXIT`：上一素材仍在场且未标记为已离场/死亡/失能/封印/消散的角色或敌人，在下一素材中因切场无故消失；或关键进门、登车、上下楼过程被 `cut` 掩盖。
- `E018 DIRECTION_FIELDS`：Schema 2.6 缺少身份锁、场景地标/光位、Hook、风险等级、高风险导演时间线、表演曲线或正式退场记录。
- `E019 COMBAT_DESIGN`：R2/R3 战斗缺少两轮攻防、技法组合或状态变化；有效动作覆盖不足；长时间使用结果展示、纯收势或抽象受力描述填充。

- `E020 CAMERA_PLAN`：H3 运镜计划缺失、连续机位跳变、固定机身与运动矛盾、变焦方向错误、硬切模式不符或运镜未同步到最终 Prompt。按 [运镜规划](camera-h3.md) 修复。
- `E023 MEDIA_BINDING`：新编译契约缺少实际媒体绑定、媒体类型错误、帧锚点职责不明确，或上传顺序与manifest不一致。旧JSON重编译也必须补全。
- `E024 STORY_TIME`：剪辑区间越界、故事时间无效、时间约束事件缺失或时差不匹配。检查的是显式提供的数据，不自动从文字推断计时。
- `E025 INNER_THEATER`：Q版变体、本体关联、叠加锚点、现实层可见性、Q版动作连续性或退场状态无效。
- `E026 INNER_AUDIO`：内心声与选定的本体/独立Q版声源、Q版可见口型、现实第一人称口型、对白时间窗口、停顿或自然语速不一致。
- `E027 DESIGN_CONTRACT`：要求严格设计复核（或外部工具启用 `--strict-design`）时，人物、场景、道具缺少可复现的外观、地标、功能或 `identity_lock`。
- `W004 ACTION_CLASSIFICATION`：未声明动作类型且出现疑似战斗词。先作语义分类；“撞上门框”“显示攻击力”不自动要求战斗设计。
- `E022 CREATURE_PROMPT`：非人单体提示词混入人类三视图模板，或缺少剪影、头部、四肢、尾部等结构锚点。按 [人物提示词编排器](character-prompt-style.md) 的非人单体分支修复。
- `E016 H3_TARGET`：`h3_mode` 与旧模式/上传素材不一致、Base/Ref2VA 字段缺失或顺序错误、帧对齐指令不在首行、参考标签不稳定、参考素材超过9图/3视频/3音频/12总数、对白/声音字段重复或 Prompt 超过7000字符。按 [H3 工业级提示词契约](h3-prompt-contract.md) 修复。

## 三、战斗语义校验

按 [连续性账本与战斗节拍](continuity-combat.md) 检查每个实际战斗幕。必须能够回答双方局面、行动目的、可见动作、对方应对、命中或落空及原因、最终收势。脚步、重心、左右手只在影响结果、道具归属或下一动作起点时要求明确。

同一幕出现三个独立伤害数字、多个换装步骤或“拾取全部物品并立即装备学习”等组合时，默认判定 `E009`。只有动作属于同一连续发力链且模型在该时长内能够清楚表现时才能保留。

## 四、修复循环

1. 按时间顺序处理最早的阻断错误，先修复上游，避免在错误状态上继续修改下游。
2. 修复范围至少包含出错素材、前一素材和后一素材。若人物位置或道具状态发生变化，继续向后传播，直到后续 `spatial_state` 与新的上游状态重新一致。
3. 缺桥接动作时，优先重新分配相邻幕时间；仍放不下就新增一个默认10秒素材。不得删除原剧本信息、加快到不可生成的动作密度或把桥接过程改成一句“已经完成”。

4. 打斗不完整时，按“局面 → 目的 → 动作 → 应对 → 结果 → 收势”重写 `combat` 和画面；必要时把复杂交锋拆幕。
5. 配音超时时，先采用符合数值播报规则的自然精简方式；不能删减剧情信息时拆分面板字段或新增素材。不得通过标注“快速播报”强行通过。
6. 空间状态改动后，同步修正第一幕、结束状态、连续性账本和最终生成提示词；检查后续素材的世界方位、持物和群体人数。镜头切换只改变画面投影时，不修改人物世界状态。
7. `E015` 修复时必须同时改正上游人物卡的正向造型、公共视觉词/`style.negative_prompt`/`style.taboos` 和受影响的人物、场景、道具参考图提示词；不得仅在旧的血腥正向描述末尾补一句“不要血腥”。
8. 每轮修复后重新执行全部结构与语义校验，不只复查刚修改的一项。只有所有 `E` 级错误为零才允许输出最终JSON。

新项目交付前复核设计完整性；绑定本地图片、音频或视频时检查文件存在。外部工具支持时可追加 `--strict-design` / `--verify-media`；仅检查地址格式不代表远程媒体已验证。

## 五、无法自动修复的情况

只有当原剧本存在互相冲突的事实，且不同修法会明显改变剧情结果时才询问用户。普通时长不足、动作拥挤、衔接缺失和配音超时不属于用户阻塞：自动拆分素材并继续校验。

风格锚点复检：用户没有明确要求真人时，`style.public_visual_prompt.zh` 必须明确包含“高精度3D写实国漫”或同等3D国漫媒介词，并且负向段独立写出“不要出现真人实拍；不要出现真人照片；不要出现真人实景；不要出现摄影棚真人肖像；不要出现写实摄影照片效果”。不得因为都市、家庭、职场或复仇题材自动切换真人。

H3 提示词复检：每条 MiniMax-H3 素材必须有 `generation.prompt_contract: "h3_official_v1"` 和明确 `generation.h3_mode`；`T2VA/I2VA/FL2VA/L2VA` 使用三个 Base 字段，`Ref2VA` 使用六个固定字段。参考图只锁定身份、外观或时间锚点，不能把完整人物三视图提示词重复复制进每条视频 Prompt。编译器输出的 `camera`、切点、稳定声源 ID 和参考标签必须是唯一事实来源。

Prompt 还要检查：负向约束只出现一次；场景/道具不得使用人物身份句式；首帧、尾帧和身份参考的 `<Picture N>` 标签不得复用；开场 `spatial_state` 不得在第一幕完整重复一遍。

人物参考图语义复检：按 [人物提示词编排器](character-prompt-style.md) 和 [用户确认的人物风格参考预设](character-style-presets.md) 逐段检查媒介、体型比例、皮肤五官、发型结构、服装材质、身份状态、固定三视图、CG布光和角色专属负向；普通人物没有无关血腥清单；脸型、发型、服装和比例有明确一致性描述；基础人物图不混入后续道具与状态；解剖、背景和人数约束符合资产类型。负向段与正向造型不得互相冲突。

服装设计语义复检：未指定服装的主角不能只交付“某色外套＋长裤＋鞋”。核对人物卡是否给出可画出的廓形、层次、材质关系和角色识别点，参考图是否完整保留；不能用堆叠饰品或“高级”形容词替代设计。用户明确要求朴素或制式时按其要求判断，不强行华丽化。若设计不足，回到人物卡修订并同步参考图与受影响的生成提示词；这项需要语义判断，结构校验通过不代表服装设计已合格。

场景与道具设计语义复检：执行 [场景与道具设计定稿](environment-prop-design.md) 的“设计复检”，核对具体设计、剧情操作、同类资产区别与卡片一致性。仅有地点/物件品类加质量词的关键资产须回到卡片补足；接口、通行和功能不能因造型升级改变。保留用户要求的朴素或空旷，不用装饰数量判断合格。
